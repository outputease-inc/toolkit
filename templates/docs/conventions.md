## Error Handling

- **Validate inputs** at system boundaries using [VALIDATION_LIBRARY]
- **Use typed errors**: Define application-specific error types (see `./errors.md`)
- **No silent catches**: Always log or re-throw; never use empty `catch` blocks
- **User-facing messages**: Return safe, generic messages; log detailed errors server-side
- **Fail fast**: Validate early, return early

## Git Conventions

### Commit Message Format

```
<type>(<scope>): <summary>

<body - explain WHY, not WHAT>
```

| Prefix | Use When |
|--------|---------|
| `feat` | New feature or capability |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `refactor` | Code restructure, no behavior change |
| `test` | Adding or updating tests |
| `chore` | Build, config, tooling |
| `wip` | Checkpoint commits (auto-generated by `/checkpoint`) |

### Branch Naming

```
NNN-feature-name
```

- `NNN`: Sequential feature number (001, 002, etc.)
- `feature-name`: 2-4 word kebab-case description
