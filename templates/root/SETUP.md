# Toolkit Setup

Finishing steps after scaffolding your project. The Eta-based scaffolder already
filled every value it could resolve from your CLI answers (project name, runtime,
package manager, commands, framework, etc.). What's left is installing
dependencies, filling the handful of remaining `[PLACEHOLDER]` tokens by hand,
and (optionally) validating.

---

## Quick Start

```bash
# 1. Install dependencies with your package manager
bun install   # or npm install / pnpm install / yarn

# 2. List any placeholder tokens still left to fill by hand
bun setup-placeholders.js

# 3. Fill toolkit.config.json (used by verify-setup.js) and any [PLACEHOLDER]
#    tokens the step above reported, editing the files directly.

# 4. Validate (optional)
bun verify-setup.js
```

> There is **no** `--apply` step. The legacy 6-phase setup pipeline was removed in
> toolkit 0.2.0 — the scaffolder now fills resolvable placeholders at scaffold
> time, and everything else is a direct hand-edit. `setup-placeholders.js` is a
> read-only inspector; it never writes.

## Before You Start

### Node.js

Some `.claude/` hooks (e.g. `protect-sensitive.js`) run under `node`, so make sure
`node` is on your PATH even for non-Node projects.

### Spec-Kit (optional, for `/speckit-*` commands)

The `specify` CLI powers the `/speckit-*` slash commands. It is only needed if you
use the spec-driven workflow.

**Source:** [github.com/github/spec-kit](https://github.com/github/spec-kit) ·
**Prerequisites:** Python 3.11+, [uv](https://docs.astral.sh/uv/), Git

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
specify init . --integration claude          # add --script ps on Windows PowerShell
specify check
```

Then run `/speckit-constitution` in a Claude Code session to establish project
principles.

## Fill Placeholders

The scaffolder resolves CLI-known tokens automatically. A few documentation tokens
(shaped like `[SOMETHING]`) remain for you to fill as your project takes shape.

```bash
bun setup-placeholders.js       # lists every remaining token + its occurrence count
bun setup-placeholders.js --help
```

Open the reported files and replace each `[PLACEHOLDER]` by hand. Unfilled
documentation tokens are harmless — they won't break any command — so fill them
incrementally.

### toolkit.config.json

`toolkit.config.json` ships with blank string fields for you to populate; it's the
config `verify-setup.js` reads. Fill the sections that apply to your project
(`project`, `tech_stack`, `commands`, `tools`, `features`, `optional`). It is
optional unless you want `verify-setup.js` to report a green check.

## Validate (optional)

```bash
bun verify-setup.js
```

Loads `toolkit.config.json` and reports `[PASS]` / `[WARN]` / `[FAIL]` for config
structure and required-field completeness. Exits non-zero on failures. Both this
and `setup-placeholders.js` import helpers from `@outputease/toolkit`, which is
already a dev dependency of your scaffold.

## Plugins (Claude Code)

Some workflow enforcement depends on Claude Code plugins. Install the ones you want:

```bash
claude plugin install hookify@claude-plugins-official
claude plugin install superpowers@claude-plugins-official
```

> Both plugins are optional. Without the `hookify` plugin, the `.claude/hookify.*.local.md`
> enforcement rules are inert (no errors, no enforcement). The superpowers plugin is optional
> as well: it provides the structured brainstorm/plan/execute workflows the skills reference.
> Without it, follow the same discipline manually: design before building, plan before
> executing, root-cause before fixing, evidence before "done".

Verify with `/plugin` inside Claude Code (Installed tab).

## Cross-Platform Notes

- The setup scripts use only Node.js `fs`/`path` — no shell commands; they run on
  Windows, macOS, and Linux.
- `.gitattributes` enforces LF line endings. Adding the toolkit to an existing repo
  with CRLF files:
  ```bash
  git add --renormalize .
  git commit -m "chore: normalize line endings via .gitattributes"
  ```
